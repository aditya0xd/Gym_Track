## Architecture Overview

```text
User (Browser / PWA)
        |
        v
  Next.js App Router (TypeScript)
        |
        +-- /owner/*         Gym Owner Portal (protected)
        +-- /superadmin/*    Superadmin Portal (protected)
        +-- /api/*           REST API Routes
               |
               +-- Prisma ORM  -->  PostgreSQL (Supabase)
               +-- Redis            Caching layer
               +-- Razorpay         Checkout + payment verification
               +-- Twilio           SMS + WhatsApp reminders
```

- App Router-based Next.js application with protected route groups per role
- Prisma service layer separates business logic from API route handlers
- PostgreSQL stores all users, members, invoices, pricing, reminders, and subscription state
- Redis provides caching to reduce database load
- Razorpay handles order creation, checkout, and signature verification
- Twilio handles outbound SMS and WhatsApp delivery with status logging

---

## Security Considerations

- Passwords hashed with bcrypt before storage
- JWT-based session strategy via NextAuth
- Separate database models for gym owners and superadmins
- Protected route groups enforce role-based access at the routing layer
- Razorpay payment signature verified server-side before marking invoices as paid
- Secrets and credentials managed via environment variables, never hardcoded

## Core User Flows

- Gym owner signs up and logs in with credentials
- Owner adds members and assigns billing duration plans
- Dashboard surfaces active, expiring, and expired memberships at a glance
- Owner sends SMS or WhatsApp reminders to members before renewals lapse
- Owner manages subscription plan and pays invoices through Razorpay checkout
- Owner downloads PDF receipts for completed payments
- Superadmin manages gym owner accounts, platform pricing, and subscription states

---

## Database Design

The schema models a multi-tenant SaaS gym-management domain:

| Model | Purpose |
|---|---|
| `AdminUser` | Gym owner tenant account |
| `SuperAdminUser` | Platform operator account |
| `Member` | Gym member linked to an owner |
| `ReminderLog` | Outbound reminder delivery history |
| `GymOwnerDurationPrice` | Owner-defined pricing per billing duration |
| `PlatformPlanPrice` | Platform-level pricing for owner subscription plans |
| `OwnerBillingInvoice` | Owner subscription billing records |

**Enums:** owner plans (`TRIAL`, `STARTER`, `PRO`), member billing durations (`ONE_MONTH` → `TWELVE_MONTHS`), reminder channels (`SMS`, `WHATSAPP`), payment and invoice lifecycle states.

## Local Development

### 1. Install dependencies

```bash
npm install
```

### 2. Create the environment file

```bash
cp .env.example .env
```

Update database and provider credentials in `.env`.

### 3. Run Prisma migrations

```bash
npx prisma migrate deploy
```

### 4. Seed demo data

```bash
npm run seed
```

### 5. Start the app

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Environment Variables

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `NEXTAUTH_SECRET` | Primary NextAuth secret |
| `NEXTAUTH_URL` | App base URL (`http://localhost:3000` for local) |
| `REDIS_URL` | Redis connection string |
| `TWILIO_ACCOUNT_SID` | Twilio account SID |
| `TWILIO_AUTH_TOKEN` | Twilio auth token |
| `TWILIO_SMS_FROM` | SMS sender number |
| `TWILIO_WHATSAPP_FROM` | WhatsApp sender number |
| `RAZORPAY_KEY_ID` | Razorpay key ID |
| `RAZORPAY_KEY_SECRET` | Razorpay key secret |
| `NEXT_PUBLIC_APP_NAME` | App display name |

> **Redis:** Use `redis://localhost:6379` for local Docker. For production, use an Upstash Redis URL from [console.upstash.com](https://console.upstash.com).

> If Twilio or Razorpay values are missing, those features will fail at runtime when invoked.
